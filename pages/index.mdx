## Overview

The IQL-Design System is organised into a layered token architecture, moving from raw values (primitives) → meaningful aliases (semantic tokens) → component-specific tokens → final UI components. This is a standard 3-tier token model used in modern design systems.

The file also includes:

- A theory section explaining the design taxonomy and rules
- A CI/CD pipeline mapping tokens to multiple platforms (Android, Web, Flutter, iOS)
- A large icon library organised by category
- A growing set of production-ready UI components

## Notes & observations

- The **token pipeline** (Primitives → Semantic → Component) is well-defined and follows industry best practice.
- **Button** and **Input** are the most developed components, with both desktop and mobile (iPhone 16, 393×852) examples.
- **Icon library** is duplicated — likely two style variants (outlined vs filled). Worth confirming and consolidating naming.
- **Empty pages**: `↳ Design Rules` is a placeholder and could be filled in.
- **Typo**: `Component / Seperator` should be `Separator`.
- Page naming uses unicode markers (`❖`, `↳`) for visual hierarchy in the Figma sidebar — clear but not searchable; consider a flat naming convention if exporting to other tools.
